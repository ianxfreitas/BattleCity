RESUMO EXECUTIVO: SOLUÇÃO PARA CARDLAYOUT COM MÚLTIPLAS INSTÂNCIAS
===================================================================

PROBLEMA RELATADO:
Na tela de GAME OVER, ao navegar para opção 2 e pressionar ENTER,
o evento era ignorado ou executado incorretamente.

CAUSA RAIZ:
Ambas as instâncias de PainelMenuAcao (PAUSE e GAMEOVER) estavam
usando WHEN_IN_FOCUSED_WINDOW, permitindo que ambas recebessem
eventos de teclado simultaneamente, causando conflito.

SOLUÇÃO IMPLEMENTADA:

┌──────────────────────────────────────────┐
│  1. Mudar WHEN_IN_FOCUSED_WINDOW para    │
│     WHEN_FOCUSED                         │
│                                          │
│  2. Adicionar setFocusable(true)         │
│                                          │
│  3. Chamar requestFocusInWindow() após   │
│     layout.show()                        │
│                                          │
│  4. Usar SwingUtilities.invokeLater()    │
│     para timing correto                  │
│                                          │
│  5. Remover conflitos (KeyListener,      │
│     métodos inexistentes)                │
└──────────────────────────────────────────┘

RESULTADO:
✅ Apenas o painel visível recebe eventos de teclado
✅ Cursor mantém o valor correto
✅ Opção 2 executa corretamente
✅ Sem interferência entre PAUSE e GAMEOVER

CONHECIMENTO ADQUIRIDO:

Este problema exemplifica um padrão comum em Swing:
- WHEN_IN_FOCUSED_WINDOW para componentes únicos
- WHEN_FOCUSED para CardLayout com múltiplas instâncias

Aplicável a:
- Múltiplos painéis no CardLayout
- Múltiplas abas em TabbedPane
- Múltiplos diálogos
- Qualquer situação com instâncias múltiplas
